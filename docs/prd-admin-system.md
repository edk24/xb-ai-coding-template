# 后台管理系统 PRD

## 1. 项目背景与目标

本项目旨在建设一个可扩展的中后台权限系统，作为后续 app / h5 业务的统一管理与接口基础。首期聚焦后台管理核心能力，完成统一登录、管理员管理、角色管理、部门管理、菜单与按钮权限管理，并提供基础日志审计能力。

目标产出：

- 一个基于 pnpm monorepo 的项目仓库
- 一个可扩展的后台前端工程（React + Ant Design 6.x + Zustand
- 一个可扩展的后台接口工程（ThinkPHP 8）
- 一套清晰的 RBAC 权限模型与基础数据关系
- 一份可直接指导开发与验收的产品 PRD

## 2. 一期范围

### 2.1 功能范围

一期纳入以下模块：

1. 登录
2. 退出登录
3. 个人资料
4. 修改密码
5. 管理员管理
6. 角色管理
7. 部门管理
8. 菜单权限管理
9. 登录日志
10. 操作日志
11. 超级管理员内置与保护机制

- 数据权限细粒度配置

- 第三方登录
- 双因子认证

## 3. 用户角色定义

### 3.1 超级管理员

系统初始化内置一个超级管理员账号，具备全部权限。

约束：

- 不可删除
- 不可禁用
- 默认拥有全部菜单与按钮权限
- 可管理其他管理员、角色、部门、菜单、日志

### 3.2 普通管理员

由超级管理员或具备相应权限的管理员创建。

特征：

- 归属一个主部门
- 可绑定多个角色
- 实际权限为多个角色权限并集
- 可登录后台并访问被授权功能

### 3.3 角色

角色是权限的承载体。

特征：

- 可绑定目录、菜单、按钮权限
- 可被多个管理员复用
- 用于降低逐人授权成本

## 4. 核心业务规则

### 4.1 组织与人员关系

- 部门为树形结构
- 管理员必须归属一个部门
- 一个管理员可绑定多个角色
- 一个角色可绑定多个管理员

### 4.2 权限模型

一期采用 RBAC 模型，权限节点分三层：

1. 目录：仅作为导航分组
2. 菜单：对应可访问页面
3. 按钮：对应页面内具体操作权限

权限规则：

- 菜单是否展示由菜单权限决定
- 页面中的操作按钮是否展示由按钮权限决定
- 接口访问权限默认由菜单/按钮权限映射控制
- 超级管理员不参与常规权限判断限制

### 4.3 密码规则

密码加密规则按既定约束实现：

```text
md5(md5(password) + salt)
```

说明：

- `salt` 为每个管理员独立随机盐值
- 后台不保存明文密码
- 该方案为既定兼容约束，不作为现代密码学最佳实践推荐

### 4.4 登录态规则

一期登录态采用 JWT。

规则：

- 登录成功返回 access token
- 后台请求通过 Authorization Bearer Token 传递凭证
- 未登录或 token 无效时跳转登录页
- 退出登录时前端清理本地 token，后端可预留黑名单/版本号机制

## 5. 功能模块设计

### 5.1 登录

#### 页面目标

让管理员通过账号密码进入后台。

#### 表单字段

- 登录账号
- 登录密码

#### 交互规则

- 提交前校验必填
- 登录中按钮置为 loading
- 登录失败提示明确错误信息
- 登录成功跳转后台首页

#### 成功条件

- 用户身份合法
- 账号状态为启用
- 密码校验通过

#### 异常场景

- 账号不存在
- 密码错误
- 账号被禁用
- token 生成失败

### 5.2 退出登录

#### 目标

让当前管理员安全退出系统。

#### 行为规则

- 点击退出后弹出确认框
- 确认后清理 token、本地用户态、菜单缓存
- 跳转登录页

### 5.3 个人资料

#### 目标

管理员可维护自己的基础信息。

#### 字段范围

- 头像
- 昵称
- 手机号
- 邮箱
- 备注

#### 规则

- 登录账号默认不可在个人资料页修改
- 手机号、邮箱可做格式校验
- 修改成功后需同步更新右上角用户信息

### 5.4 修改密码

#### 目标

管理员可修改自己的登录密码。

#### 字段

- 原密码
- 新密码
- 确认新密码

#### 规则

- 原密码必须校验正确
- 新密码与确认密码必须一致
- 修改成功后建议重新登录

### 5.5 管理员管理

#### 目标

维护后台管理员账号。

#### 列表字段

- ID
- 头像
- 登录账号
- 昵称
- 手机号
- 邮箱
- 所属部门
- 绑定角色
- 状态
- 备注
- 创建时间

#### 支持操作

- 新增管理员
- 编辑管理员
- 查看管理员详情
- 启用/禁用管理员
- 重置密码
- 删除管理员（超级管理员不可删）

#### 新增/编辑字段

- 登录账号
- 昵称
- 头像
- 手机号
- 邮箱
- 所属部门
- 绑定角色（多选）
- 状态
- 备注

#### 规则

- 登录账号全局唯一
- 管理员必须归属一个部门
- 管理员可绑定多个角色
- 超级管理员不可删除、不可禁用
- 重置密码后可采用系统默认密码或管理员输入新密码，具体实现阶段固定

### 5.6 角色管理

#### 目标

统一维护权限角色。

#### 列表字段

- ID
- 角色名称
- 角色编码
- 状态
- 备注
- 创建时间

#### 支持操作

- 新增角色
- 编辑角色
- 删除角色
- 启用/禁用角色
- 分配菜单/按钮权限

#### 规则

- 角色名称唯一
- 角色编码唯一
- 角色删除前应校验是否已绑定管理员
- 角色权限变更后，相关管理员重新获取权限时应生效

### 5.7 部门管理

#### 目标

维护树形部门结构。

#### 字段建议

- 部门名称
- 上级部门
- 排序值
- 负责人
- 联系电话
- 状态
- 备注

#### 规则

- 部门为树结构
- 不允许形成循环父子关系
- 删除部门前需校验是否存在子部门或管理员归属

### 5.8 菜单权限管理

#### 目标

维护系统导航与按钮权限节点。

#### 节点类型

- 目录
- 菜单
- 按钮

#### 字段建议

- 名称
- 类型
- 父级节点
- 路由路径
- 组件路径
- 权限标识
- 图标
- 排序值
- 状态
- 是否隐藏
- 备注

#### 规则

- 目录用于导航分组
- 菜单用于路由与页面访问控制
- 按钮用于页面操作权限控制
- 权限标识需全局可读且具有唯一性

### 5.9 登录日志

#### 记录内容

- 登录账号
- 登录结果
- 登录 IP
- 登录设备/浏览器信息
- 登录时间
- 失败原因

### 5.10 操作日志

#### 记录内容

- 操作人
- 操作模块
- 操作类型
- 请求方法
- 请求路径
- 请求参数摘要
- 响应结果摘要
- 操作 IP
- 操作时间

## 7. 页面交互原则

- 整体风格采用暗黑、简约、朴素风格
- PC 为主，兼顾手机端访问
- 手机端优先保障登录、查看、基础编辑等核心链路可用
- 复杂表格页在手机端允许横向滚动、抽屉表单、字段折叠
- 权限不足时不展示无权按钮
- 无数据时提供空状态提示

## 11. 安全与权限约束

- 所有后台接口默认需要 JWT 鉴权，登录接口除外
- 所有管理动作需要进行权限校验
- 超级管理员受保护，不可删除、不可禁用
- 删除角色、部门前应校验关联关系
- 关键管理操作需记录操作日志
- 前端按钮展示仅作为体验控制，后端必须做真实权限校验

## 12. 一期验收标准

### 12.1 登录验收

- 正确账号密码可登录
- 错误密码被拒绝
- 被禁用账号无法登录
- 登录后刷新页面仍可保持登录态

### 12.2 管理员管理验收

- 可新增管理员并绑定部门与多个角色
- 可编辑管理员资料
- 可启用/禁用管理员
- 可重置管理员密码
- 超级管理员不可删除、不可禁用

### 12.3 角色管理验收

- 可新增、编辑、删除角色
- 可为角色分配目录、菜单、按钮权限
- 角色权限变更后相关管理员重新登录可生效

### 12.4 部门管理验收

- 可新增、编辑树形部门
- 删除部门时能正确校验子部门与成员占用

### 12.5 菜单权限验收

- 可维护目录、菜单、按钮节点
- 角色授权后前端菜单与按钮展示符合预期

### 12.6 个人资料验收

- 当前管理员可修改个人资料
- 当前管理员可修改自己的密码
- 修改密码后旧密码失效

### 12.7 日志审计验收

- 登录成功/失败均记录日志
- 新增、编辑、删除、授权、重置密码等关键动作记录操作日志

## 13. 后续扩展建议

- 在接口命名与认证层预留 app / h5 业务分组，例如 `/app-api/*`
- 后续若引入多端统一账号体系，可在现有 JWT 方案基础上扩展 token 类型与终端标识
- 后续若引入数据权限，可在角色基础上补充部门数据范围、个人数据范围等模型
- 后续若引入多租户，可在现有实体表上增加 tenant_id 并扩展隔离规则
